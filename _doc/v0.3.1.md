# NQU-ERP v0.3.1 Release Notes

## 版本概述

v0.3.1 為 v0.3 的小改版，讓**管理員可修改與刪除**帳號與課程，補足「只能新增」的缺口。

## 後端新增 API

| Method | Path | 角色 | 說明 |
|--------|------|------|------|
| PUT | `/api/v1/admin/users/{user_id}` | Admin | 修改姓名/角色/科系/Email，密碼留空不變、有值則重設 |
| DELETE | `/api/v1/admin/users/{user_id}` | Admin | 刪除帳號（無法刪除自己 / 有授課的教師 / 有選課的學生） |
| PUT | `/api/v1/admin/courses/{course_id}` | Admin | 修改課程（代碼/名稱/教師/學分/名額/科系） |
| DELETE | `/api/v1/admin/courses/{course_id}` | Admin | 刪除課程（含其時段、選課與成績紀錄，transaction 處理） |

另外 `GET /courses` 新增 `teacher_id`、`dept_id`；`GET /admin/users` 新增 `dept_id`，供編輯表單預填。

### 刪除防護規則

- 不能刪除自己（admin 刪除本人 → 400）
- 教師尚有授課課程 → 400「該教師尚有授課課程，無法刪除」
- 學生尚有選課紀錄 → 400「該學生尚有選課紀錄，無法刪除」
- 課程刪除會一併清除 `class_schedules`、`enrollments`、`grades`（transaction，避免 FK 孤立）

## 前端變更

- `UserForm` / `CourseForm` 支援 `initial` 屬性切換編輯模式：
  - 按鈕變為「儲存修改」，送出中為「儲存中...」
  - 帳號（username）在編輯時鎖定不可改、密碼欄位可留空
  - 送出後回到新增模式（清空表單）
- `AdminUsers`：列表新增「操作」欄（編輯 / 刪除），編輯會把該筆資料帶入表單；刪除有 `window.confirm` 確認
- `AdminCourses`：課程卡片新增「編輯 / 刪除」按鈕，邏輯同上
- 新增「取消編輯」按鈕可退回新增模式

## 測試

```bash
bash test.sh        # 後端 72 tests（新增 24 項：權限 403、改名/改密碼生效、舊密碼失效、
                    #   防刪保護 400、刪除後數量歸位、重複刪除 404 等）

cd frontend
bash test.sh        # Vitest 26 + Playwright E2E 10
npm test            # 僅 Vitest（jsdom）
npx playwright test # 僅 E2E
```

- Vitest 新增：UserForm / CourseForm 編輯模式（預填、鎖定帳號、密碼可選、送出值正確）
- E2E 管理員段落改為完整旅程：新增帳號 → 修改（改名+改密碼）→ 搜尋 → 刪除；開設新課程 → 修改 → 刪除
- E2E 陷阱補充：刪除成功訊息為「帳號 {username} 刪除成功」格式，搜尋文字要避開被中斷的 substring

## 已知限制

- 帳號的 `username` 一經建立不可修改（作為登入識別）
- 課程刪除為硬刪除（移除選課資料），正式系統宜改為「停用」狀態
- 課程編輯不支援時段（class_schedules）維護 → v0.4
