## 2　為什麼是 kind

本機現況只有 docker（無 kubectl / minikube / kind / k3d / helm / k9s）——而 **kind 是唯一「跑在現有 docker 之上、不用 VM 層、本機當下就完整」的選擇**：

- ✅ 不需要另行裝 VM / hypervisor（minikube 的 driver 層免談）
- ✅ 用**同一顆 docker**長出「偽多節點」（3 節點模擬 → 直接滿足「主機數 ≥ 2」的假設）
- ✅ 部署**不必重編譯**——GHCR 已有 `ghcr.io/ccc115a/nqu_erp-api:main`（書 6.2 / v0.5 CD 成品）

> 一句話：**「展示練習」跟「上線」的差別不在工具，在「有沒有誠實」——本版先不造假任何容量數字。**

## 4　執行關卡（**已親眼走完，底下每列都打過真勾**）

| # | 關卡 | 親眼證據（不打假勾） | 勾 |
|---|------|----------------------|----|
| 1 | `kind create cluster --config deploy/k8s/kind-config.yaml` | `kind get clusters` → `nqu-erp`；`kubectl get nodes` 見 **control-plane + worker + worker2＝3 台（判準「主機數 ≥ 2」✅）** | ✅ |
| 2 | `kind load docker-image nqu_erp-api:latest` | 本機映像灌進 3 node，deployment `image: nqu_erp-api:latest`＋`IfNotPresent`（**零 GHCR 依賴，401 不必等**） | ✅ |
| 3 | `kubectl apply -f deploy/k8s/api.yaml`＋等 rollout | **3/3 api pod Running**（之前 CrashLoop 的全死因見下表「真教訓」） | ✅ |
| 4 | `/health` 親眼 200 | `port-forward svc/nqu-erp-api 18080:80` ＋ `curl 127.0.0.1:18080/health` → **HTTP 200**（使用者親手 forward、親眼勾） | ✅ |

> **真教訓（Code 14 → emptyDir）**：api 映像開檔 `sqlite:///data/nqu.db`（code 14 = SQLITE_CANTOPEN）會 CrashLoop，因為 **pod 的檔案系統是全新的、`/data` 不存在**——本機 dev 的「CWD 下自動有 data/」是假設，pod 裡沒有。解法是 **k8s 語彙不是程式碼**：`emptyDir` volume 掛到 `/data`（kubelet 養目錄），Rust 一行不改、判準照勾。

> **最後一道防線**：功能線 `bash test.sh` 仍全綠、`node_modules` 版 `npm test` 不打假——練習線加資產**不許弄壞功能線**（v2.1 起每版都先立這道防線）。
