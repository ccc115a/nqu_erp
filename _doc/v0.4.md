# NQU-ERP v0.4 — Docker 部署規劃

## 版本概述

v0.4 的核心目標：讓整套校務系統（後端 API + 前端 Web）可以透過 **Docker** 一鍵部署到任何支援 Docker 的環境（本機、測試機、雲端 VM），並以 **PostgreSQL** 取代開發用的 SQLite 作為正式資料庫。

## 部署架構

```
┌───────────────┐   :80  同源（nginx 反向代理，免 CORS）
│     web       │  nginx:alpine
│  frontend     │  ── 靜態檔 + SPA fallback ──┐
│  (VITE dist)  │  location /api { proxy_pass } │
└──────┬────────┘                              │
       │  internal network（compose 預設）      │
┌──────▼────────┐   :8080                      │
│      api      │  Rust release binary         │
│  backend      │  ── 啟動時自動跑 migration ─┐│
└──────┬────────┘  /health 供 healthcheck     ││
       │                                     ││
┌──────▼────────┐   :5432                    ││
│       db      │  postgres:16-alpine  ◄──────┘│
│ PostgreSQL    │  volume: pgdata（資料持久化）│
└───────────────┘                              ┘
```

- 前端與後端同源部署：瀏覽器只打 `:80`，`/api/*` 由 nginx 轉發到 `api:8080`。
- 後端啟動時會自動執行 migration（既有行為），資料表建好後即可喂入 seed。

## docker-compose 服務設計

| 服務 | 映像 | 說明 |
|------|------|------|
| `db` | `postgres:16-alpine` | PostgreSQL 資料庫；`pgdata` volume 持久化；`pg_isready` healthcheck |
| `api` | 自建（`Dockerfile`） | Rust release binary；`environment` 注入 `DATABASE_URL` / `JWT_SECRET` / `SERVER_ADDR`；`/health` healthcheck |
| `web` | 自建（`frontend/Dockerfile`） | Node 建置 dist → nginx 提供靜態檔並代理 `/api`；對外開 `80:80` |
| `seed` | `postgres:16-alpine`（一次性） | 用 `psql` 套用 `scripts/seed.sql`；掛 `profiles: ["seed"]`，`docker compose --profile seed run --rm seed` 執行 |

> 註：`api` 亦**不對外暴露 host 8080**（僅 container 內部 :8080）。本機 `test.sh` 佔用 `localhost:8080`，若 docker 同時綁 8080 會打到容器造成誤測（實測 66/72）。docker 外所有 API 一律經 nginx 同源 `http://localhost/api/v1`。

### 服務相依與健康檢查

- `api` 依賴 `db` 的 `service_healthy`（等 PostgreSQL 就緒再連線）。
- `web` 依賴 `api` 的 `service_healthy`（等 `/health` OK 再開給使用者）。
- `db`／`api` 皆設定 healthcheck，失敗時 compose 會依照 policy 重試／重啟。

### 後端 Dockerfile（概念）

```dockerfile
# ---- builder：編譯 release binary ----
FROM rust:1.84-slim AS builder
WORKDIR /app
COPY Cargo.toml Cargo.lock ./
COPY migrations/ ./migrations/
COPY src/ ./src/
RUN cargo build --release

# ---- runtime：只帶 binary + 憑證 ----
FROM debian:bookworm-slim
RUN apt-get update && apt-get install -y --no-install-recommends ca-certificates curl \
    && rm -rf /var/lib/apt/lists/*
COPY --from=builder /app/target/release/nqu-erp /usr/local/bin/nqu-erp
EXPOSE 8080
HEALTHCHECK CMD curl -sf http://localhost:8080/health || exit 1
CMD ["nqu-erp"]
```

### 前端 Dockerfile + nginx（概念）

```dockerfile
# ---- build：Vite 建置，設定同源 API 路徑 ----
FROM node:20-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
ARG VITE_API_BASE=/api/v1
ENV VITE_API_BASE=$VITE_API_BASE
RUN npm run build

# ---- runtime：nginx 提供靜態檔並代理 /api ----
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

`nginx.conf` 重點：

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;

    # SPA fallback：沒對應到靜態檔就回 index.html
    location / {
        try_files $uri /index.html;
    }

    # 同源 API 代理
    location /api/ {
        proxy_pass http://api:8080;
        proxy_set_header Host $host;
    }
}
```

## 前端／後端設定調整

### 前端 API base（必要）

`src/api/client.ts` 目前把 baseURL 寫死為 `http://localhost:8080/api/v1`，docker 部署必須同源。改為：

```ts
export const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE ?? 'http://localhost:8080/api/v1',
})
```

- 本機 dev：`frontend/.env` 設 `VITE_API_BASE=http://localhost:8080/api/v1`（行為不變）。
- Docker：`frontend/Dockerfile` 的 `ARG VITE_API_BASE=/api/v1`。

### 後端 CORS origin（配合調整）

同源部署時瀏覽器不再跨來源，CORS 不再需要。為保留本機 dev 流程，`Config` 新增 `cors_origin`：

```txt
CORS_ORIGIN=http://localhost:5173    # 缺省值，dev 用
CORS_ORIGIN=*                        # docker 同源部署可放行（或省略）
```

## 部署方式

```bash
# 1. 產生假資料 SQL（需 python3 + bcrypt，僅在 host 執行一次）
python3 scripts/seed.py -o scripts/seed.sql --seed 42

# 2. 啟動 db + api + web（--wait 等全部 healthy）
docker compose up -d --wait --build

# 3. 喂入假資料（一次性；seed 掛 profile 不會被 up 自動啟動）
docker compose --profile seed run --rm seed
#    套用 seed.sql 並同步 auto-increment sequence（seed 用顯式 id 寫入）
#    → docker_test.sh 自動處理，手動操作時需補 psql setval

# 4. 瀏覽 http://localhost ，驗證登入/選課/成績/管理功能
#    測試帳號：admin / admin123，T001 / teacher123，11303001 / student123
# 5. 完整建置＋整合測試（23 項）：bash docker_test.sh
#    全過 → stack 保持上線；加 --down 可收尾關閉
```

重啟／更新：

```bash
docker compose down          # 停止（pgdata volume 保留資料）
docker compose down -v       # 停止並清除資料（重新開始）
docker compose build && docker compose up -d   # 更新程式碼後重建
```

## 驗證

- `docker compose config` — 確認 compose 語法與環境變數注入正確。
- `docker compose up -d --wait` 後：
  - `docker compose exec -T api curl -sf http://localhost:8080/health` 回傳 `OK`（api 不對外暴露，健康檢查進容器內執行）。
  - `docker compose ps` 顯示 `db`/`api`/`web` 皆 healthy。
- seed 後課程數 = 15、帳號數 = 42（與本機 `test.sh` 相同基準）。
- 前端不用 `docker` 的本機流程維持不變：`npm install && npm run dev`。

## 已知限制

- seed 需在 host 先以 python3 產生 `seed.sql`（rust runtime 映像不含 python）。
- `docker compose` 預設使用 SQLite 的開發流程不受影響；正式環境一律走 PostgreSQL。
