# NQU-ERP v0.5 — CI/CD（GitHub Actions + GitHub Container Registry）

## 版本概述

v0.5 的目標：把「品質關卡」與「發佈」自動化。利用 GitHub Actions，在 **push main 與所有 PR** 上自動跑完整品質關卡（後端 + 前端 + Docker 整合），並在合併到 main 時自動 **build + push 三個核心映像**到 GitHub Container Registry（GHCR）。實際部署維持「手動」——在目標主機可用 GHCR 映像一鍵 `docker compose pull` 上線，CI/CD 不需持有正式 server 的 SSH 金鑰。

## 目標 vs 非目標

| | 內容 |
|---|---|
| ✅ 目標 | 每個 push/PR 自動重跑 v0.3 起的全套測試（後端 `test.sh`、前端 Vitest+Playwright、Docker `docker_test.sh`） |
| ✅ 目標 | push 到 main 自動 build 並 push `nqu_erp-api`、`nqu_erp-web` 映像到 GHCR，並推送 db seed 產物 |
| ❌ 非目標 | 自動部署到正式 server（無正式 server；部署留手動 `docker compose pull`） |
| ❌ 非目標 | 在 CI 內跑 `docker_run.sh`（上線/維運腳本，不屬驗證；驗證歸 `docker_test.sh`） |

## CI/CD 架構

```
    push main / PR
         │
         ▼
   ╔═════════════════════════╗
   ║  .github/workflows/ci.yml║   PR 與 main 都跑
   ╚═════════════════════════╝
         │
         ├─ job: backend   ── cargo fmt --check ├ cargo clippy ─ cargo build
         │                    cargo test ─ bash test.sh（72 項，需 SQLite + seed）
         ├─ job: frontend  ── npm ci ─ Vitest（26）─ Playwright E2E（10，dev.db）
         └─ job: docker    ── docker build ├ docker compose build
                              bash docker_test.sh（23 項，docker compose --profile seed）
         │（合併到 main 才觸發）
         ▼
   ╔══════════════════════════╗   push main
   ║  .github/workflows/cd.yml ║
   ╚══════════════════════════╘
         │
         └─ job: build-push ── docker buildx build --push
                                ghcr.io/ccc115a/nqu_erp/{api,web}:main
                                （GHCR，GITHUB_TOKEN 自動登入）
```

## GitHub Actions：ci.yml

```yaml
name: ci
on:
  push:
    branches: [main]
  pull_request:
  workflow_dispatch:

jobs:
  backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - name: fmt
        run: cargo fmt --check
      - name: clippy
        run: cargo clippy --all-targets -- -D warnings
      - name: build
        run: cargo build
      - name: test
        run: bash test.sh   # build → server → seed → 72 API 測試 → kill
  frontend:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: frontend } }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm, cache-dependency-path: frontend/package-lock.json }
      - run: npm ci
      - run: bash test.sh     # seed → Vitest 26 → Playwright E2E 10
  docker:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: build 映像
        run: docker compose build
      - name: 整合測試
        run: bash docker_test.sh   # 每次重建 + seed + 23 項
```

> 註：CI 不執行 `docker_run.sh`（那是維運不是驗證）。`docker_test.sh` 已內含完整的「建置 → 啟動 → seed → 測試 → 收尾」。

## GitHub Actions：cd.yml（合併 main → push 映像）

```yaml
name: cd
on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  build-push:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write          # 推 GHCR 需要
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with: { registry: ghcr.io, username: ${{ github.actor }}, password: ${{ secrets.GITHUB_TOKEN }} }
      - name: build+push api
        uses: docker/build-push-action@v5
        with:
          context: .
          file: Dockerfile.api
          push: true
          tags: ghcr.io/ccc115a/nqu_erp/api:main
          cache-from: type=gha
          cache-to: type=gha,mode=max
      - name: build+push web
        uses: docker/build-push-action@v5
        with:
          context: frontend
          file: frontend/Dockerfile
          push: true
          tags: ghcr.io/ccc115a/nqu_erp/web:main
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

> 發版用 `main` tag（可再加 `sha-<短碼>`）。之後要收 stable 版可打 git tag `v0.5.0` 推 `:v0.5.0`。

## 部署（手動，未自動化）

目標主機只要裝 Docker，即可一鍵拉取與上線：

```bash
# 在目標主機（先登入 GHCR）
echo "$GHCR_TOKEN" | docker login ghcr.io -u ccc115a --password-stdin

docker compose pull                          # 拉取 GHCR 映像
WEB_PORT=80 docker compose up -d --wait      # 上線（資料 volume 持久化）
```

> 若目標主機停止對外 pull，可設 `GHCR_TOKEN` 為 fine-grained PAT（`packages:read`）。

## Secrets / 設定

| 項目 | 值 | 備註 |
|---|---|---|
| `GITHUB_TOKEN` | 自動提供 | CI 用於 checkout；CD 用於 `packages:write`（不需手動建） |
| GHCR token（僅部署主機用） | 你手動建 | `packages:read`，供目標主機 `docker login` |

Actions 不需任何 secret 即可跑：後端/前端測試用 `dev.db` 與 `scripts/seed.sql`（seed 由 test.sh 內部產生），權限全在 repo 內。

## 與既有測試對齊

| 測試 | CI job | 數量 | 資料來源 |
|---|---|---|---|
| `cargo fmt / clippy / build` | backend | - | 無（靜態檢查） |
| `bash test.sh` | backend | 72 | SQLite `dev.db` + seed |
| Vitest | frontend | 26 | jsdom（無 DB） |
| Playwright E2E | frontend | 10 | dev.db + seed |
| `bash docker_test.sh` | docker | 23 | Docker db（Postgres）+ seed |
