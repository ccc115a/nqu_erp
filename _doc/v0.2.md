# NQU-ERP v0.2 Release Notes

## 版本概述

金門大學校務系統 MVP v0.2，實作**學生端 React 介面**（Student Frontend），並在後端加入 CORS 支援。本版本建立在 v0.1 後端 API 之上，是首個可視覺化操作的版本。

## 後端變更（本版本必須）

### CORS 設定

前端開發伺服器（Vite, `http://localhost:5173`）與後端（`:8080`）為不同 origin，需在後端加入 CORS middleware：

**`Cargo.toml`：**

```toml
tower-http = { version = "0.6", features = ["cors"] }
```

**`src/main.rs`：**

```rust
use tower_http::cors::{Any, CorsLayer};

let cors = CorsLayer::new()
    .allow_origin("http://localhost:5173".parse::<HeaderValue>()?)
    .allow_methods(Any)
    .allow_headers(Any);

let app = Router::new() ... .layer(cors).with_state(state);
```

## 頁面設計

### 登入頁 `/login`

- 帳號 / 密碼表單，送出至 `POST /auth/login`
- 成功後將 token 存 `localStorage`，依角色導向：
  - 學生 → `/courses`
  - 教師 / 管理員 → 顯示「請使用 v0.3」訊息（本版不實作）
- 失敗顯示後端錯誤訊息（`{ "error": "帳號或密碼錯誤" }`）

### 課程瀏覽頁 `/courses`

- 列表呈現：課程名稱、教師、學分、名額（`enrolled_count/capacity`）、時間地點
- 搜尋列：依名稱模糊篩選
- 加選按鈕：呼叫 `POST /enrollments`，成功 toast「加選成功！」
- 已選課程顯示「已選修」禁用；衝堂/額滿顯示後端錯誤訊息
- 已選課程出現「退選」按鈕：`DELETE /enrollments`

### 個人課表 `/schedule`

- `WeeklySchedule` 以 CSS Grid 呈現（星期 × 節次 1~14）
- 課程為色塊，標示課程名稱 + 教室；懸停顯示教師與時段

### 歷年成績 `/grades`

- `GradeTable` 列出：課程、期中、期末、總分、送交狀態
- `is_submitted = false` 顯示「未送交」標籤

## API 串接慣例

- `api/client.ts` 建立 Axios instance：`baseURL: 'http://localhost:8080/api/v1'`
- 請求 interceptor：從 `localStorage` 讀取 token，附加 `Authorization: Bearer <token>`
- 收到 401 清除 token 並導回 `/login`
- 錯誤統一顯示後端 `{ "error": "..." }` 訊息

## 測試

```bash
bash test.sh                    # 後端 33 tests 必須全數通過（CORS 變更不得影響）

cd frontend
bash test.sh                    # 前端：build → seed → Vitest(11) → Playwright E2E(7)
npm test                        # 僅 Vitest 單元測試
npx playwright test             # 僅 Playwright E2E（會自動起 Vite :5173）
```

`frontend/test.sh` 會自動：`cargo build` → 啟動後端（輪詢 `/health`）→ `seed.py --seed 42` → 驗證課程數 `= 15` → Vitest 單元測試 → Playwright E2E（含登入、搜尋、加選→課表→成績→退選完整流程、重複加選拒絕、登出）。

### 已知 E2E 陷阱

- 測試帳號密碼：`11303001` / `student123`
- 後端規則「**退選後不可重選**」：加退選 E2E 必須各用獨立課程（`計算機網路 course 3` 給 journey，`控制系統 course 8` 給重複加選測試），避免測試彼此污染狀態
- Playwright `request` fixture 的 `Authorization` header 需手動加 `Bearer ` 前綴
